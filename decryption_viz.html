SudoSOC Core Security Concepts

🎯 MITRE ATT&CK Framework

SudoSOC maps intercepted behaviors directly to the MITRE ATT&CK® framework. When the AI engine detects high-entropy data (e.g., Exfiltration) or SQL syntax in web traffic, it tags the alert with specific Tactics (like TA0010 - Exfiltration) and Techniques (like T1048 - Exfiltration Over Alternative Protocol), allowing SOC analysts to understand the adversary's exact position in the cyber kill chain.

🛡️ Secure Sniffing & Certificates

To intercept traffic, SudoSOC acts as a transparent proxy. It presents a dynamically generated SSL Certificate to the client (acting as the server) while maintaining a separate connection to the actual destination. This Man-in-the-Middle (MitM) technique allows secure sniffing, provided the client trusts the SudoSOC root CA.

🔓 Out-of-Band Decryption (SSLKEYLOGFILE)

Modern browsers use Perfect Forward Secrecy (PFS), meaning the private certificate key isn't enough to decrypt traffic. Instead, SudoSOC forces the browser to export the symmetric Pre-Master Secret Keys to a secure file using the SSLKEYLOGFILE environment variable. The SudoSOC engine reads these keys out-of-band to decrypt the packets seamlessly without breaking certificate trust.

Browser Key Extraction Mechanism

By injecting the SSLKEYLOGFILE environment variable, SudoSOC forces Chromium/Gecko based browsers to dump the pre-master secrets used for TLS 1.2/1.3 sessions. This allows our backend to decrypt traffic out-of-band without complex certificate spoofing.

# sudo_soc_key_hook.py import os import subprocess # Define secure path for key logging key_log_path = "C:\\sudosoc_keys\\tls_secrets.log" # Inject environment variable for the browser process os.environ["SSLKEYLOGFILE"] = key_log_path # Launch Target Browser (Chrome example) print(f"[*] Launching browser with TLS key extraction enabled -> {key_log_path}") subprocess.Popen([ "C:\\Program Files\\Google\\Chrome\\Application\\chrome.exe", "--ignore-certificate-errors" ])
